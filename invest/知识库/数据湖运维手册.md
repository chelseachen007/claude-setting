# 数据湖日常运维手册

> 2026-11-12 建立。起因：10-30 之后数据湖静默停了 13 天，看板一直「健康」，
> 没有任何人收到通知。这份手册写清楚「怎么知道它活着」「坏了怎么修」。

## 一、现在的结构

| 部件 | 是什么 | 在哪 |
|---|---|---|
| 看板服务 | `cne-wb serve`，端口 8787 | `~/Library/LaunchAgents/com.cnequity.lake-serve.plist`（KeepAlive） |
| 调度器 | cnequity 自带，每分钟唤醒一次、自己限流到 15:30 / 18:00 | `~/Library/LaunchAgents/com.cnequity.web.706c3d40b7beb570.plist` |
| 看门狗 | 工作日 15:10 判断「今天抓到没」，没抓到就弹通知 | `~/Library/LaunchAgents/com.user.lake-watchdog.plist` |
| 数据 | `data/cnequity/curated/*`（parquet） | 只通过 `cne` 操作，不手改 |

调度器 label 里的 16 位指纹 = `sha256(meta_root.resolve())[:16]`，见
`.venv/lib/python3.13/site-packages/cnequity/serve/ops/scheduler_backend.py:57-60`。
**换工作区目录（换 meta_root）会让 label 变**，要重新 apply 一次调度。

## 二、每天会发生什么

- **15:30** 调度器触发 `daily` 全量：core 组先跑，`daily_bars` 约 13 分钟写完当日 5500+ 只票。
- **17:00 起** 依次跑 capital / signals / fundamentals / macro_risk / research / derivatives。
- **15:10** 看门狗判断一次（在日更之前，所以它看到的是「上一轮有没有抓到」）。
- 手动/定时任务共用 `daily_ingestion.lock`，**同一时刻只允许一个 daily 在跑**。

## 四、常见故障与处置

### 1. 数据落后了几天

```bash
# 看欠账
.venv/bin/python3 -c "import json;d=json.load(open('data/cnequity/meta/state/daily_bars.json'));print(d['coverage_status'],d['complete_through'],d['observed_max']);print(d['outstanding_keys'])"

# 按交易日逐天补（把日期换成缺的那天，一天一条）
.venv/bin/python3 工具/数据湖/cne_clean.py run daily --trade-date 2026-11-03 --group core --config 配置/cnequity.toml
```

**不要**直接跑 `cne run daily` 补历史：`signals` 组里的 `dragon_tiger` / `block_trades`
一旦吃到历史缺口，会从 2007 年起逐日扫（约 6 年/小时，全程 6-7 小时），期间锁被占住，
其他组全被拒。要补 K 线就指定 `--group core`。

### 2. 任务卡住不结束

`POST /api/ops/jobs/<id>/cancel` 会返回 202 但**对卡住的进程无效**。实测：

```bash
kill -TERM <pid>   # 0.6 秒退干净，job 记录成 lost
```

`SIGINT` 反而要 11 秒且未必退。**用 SIGTERM。**

被 kill 的进程如果还挂着 `daily_ingestion.lock`，后面的任务会报
"Another daily group is still running"。确认没有 cne 进程后再跑。

### 3. 报 `Invalid port: ':1]'`

httpx 0.28.1 解析 `NO_PROXY` 里的 `[::1]` 会炸，东财请求全挂。**手动跑一律用包装脚本**：

```bash
.venv/bin/python3 工具/数据湖/cne_clean.py <cne 的参数...>
```

它会删掉所有代理变量（本机所有源直连都通），并给 `public-api.baostock.com`
换成真实 IP（Clash fake-ip 会让裸 socket 连不上）。

### 4. 想手动跑一次日更（走看板接口）

字段名只有 `preview_id` 和 `launch_token`，多传会 422：

```bash
CSRF=$(curl -s --noproxy '*' http://127.0.0.1:8787/api/ops | python3 -c "import json,sys;print(json.load(sys.stdin)['csrf_token'])")
P=$(curl -s --noproxy '*' -X POST http://127.0.0.1:8787/api/ops/preview \
  -H "Content-Type: application/json" -H "Origin: http://127.0.0.1:8787" -H "X-CNE-CSRF: $CSRF" \
  -d '{"op":"daily.full","params":{"trade_date":"2026-11-12","backfill":false,"no_events":false,"pack":[]}}')
PID=$(echo "$P" | python3 -c "import json,sys;print(json.load(sys.stdin)['preview_id'])")
LT=$(echo "$P" | python3 -c "import json,sys;print(json.load(sys.stdin)['launch_token'])")
curl -s --noproxy '*' -X POST http://127.0.0.1:8787/api/ops/jobs \
  -H "Content-Type: application/json" -H "Origin: http://127.0.0.1:8787" -H "X-CNE-CSRF: $CSRF" \
  -d "{\"preview_id\":\"$PID\",\"launch_token\":\"$LT\"}"
```

### 5. 中午别跑日更

A 股当日 K 线在 15:05 前拒绝写入（`bars.py:103`），中午跑只能拿到前序数据，
还会把 `valuation_metrics` / `fund_flow` 打成 source unavailable。**15:05 之后再跑。**

## 五、已知的、不算问题的

- `coverage_status` 长期 `incomplete`：只要 `outstanding_keys` 是那几只停牌/退市票就是误报。
  - `688121.SH 2026-10-29`：*ST卓然，退市整理，当天无成交；已实测重抓 0 行。
  - `301139.SZ 2026-11-03`：`trading_status` 标 delisted，库里最后一条是 10-27。
  - `920085.BJ 2026-11-02/03`：北交所新票，增量窗口拿不到，重跑该日 core 可补。
- `missing_ranges` 里出现 `bj_price_limit`：`storage/staged_contracts.py:38` 的北交所
  涨跌停校验会把 688xxx 这类**科创板**票错当北交所，退市僵尸价（0.4 元连续多日）于是被判违规。
- 5 个 STALE（commodity_bars / index_constituents / industry_members / macro_indicators /
  market_breadth）：它们的 schedule group 没配或没跑，`cne check` 会把「没调度」算成 stale。
  不影响行情数据本身，看板「数据新鲜度」里会看到，属已知偏差。
- `push2.eastmoney.com` 在代理出口被上游断开（TLS 后立即 RemoteProtocolError），
  `fund_flow` 只能等次日补；这不是配置错误。
- **`push2` 一熔断就是半天**：`eastmoney_guard.json` 里 `strikes_needed = 1`，一次
  RemoteProtocolError 就把 `push2.eastmoney.com` 关到当天结束（熔断由 15:30 定时切到次日）。
  这期间单票补数会掉到 baostock 兜底，而 baostock 在国内被**连接重置**（login 报
  `10002007 网络接收错误`，出口 IP 是 Clash 的 198.18.0.1）——所以**白天补历史单票基本补不上**，
  要等次日。这也解释了 `2026-11` 期间个别票（000831.SZ / 002129.SZ / 002717.SZ 的 11-02）
  只在某一天缺、之后又正常。
- `920085.BJ` 在 `daily_bars` 里只有 2026-11-12 一天——这是**新股**，前面没历史是正常的；
  它的 11-02/11-03 欠账无害，下次增量跑到就会自然消失。

# Pixel Replicate

从目标页面提取精确 DOM 结构和 CSS 值，对比现有代码，逐项修正至像素一致。

## 核心原则

**DOM 结构是唯一真相来源，截图仅作视觉参考。**

- 截图可能被反爬机制、缓存、懒加载误导（显示"页面未找到"但截图仍有内容）
- SPA 框架的内容通过 JS 动态渲染，截图和 DOM 可能不同步
- 必须先拿到 DOM 树，再用截图辅助理解视觉效果

## 流程

1. **调查（DOM 优先）**
   - 第一步：用 CDP eval 提取 `.main` 或主容器的 DOM 树结构（深度限制 6 层）
   - 第二步：截图建立视觉基线（仅作辅助参考）
   - 第三步：对关键区域提取 computed style
   - 如果目标页面被反爬拦截（显示"页面未找到"、弹验证码等），**优先提醒用户手动处理**：
     a. 告知用户："页面触发了反爬验证，请在你的浏览器中完成验证，完成后告诉我继续"
     b. 等待用户确认完成后，刷新页面重新提取 DOM
     c. 如果用户无法处理，再使用降级策略：换 URL 路径 / 找同类有效页面 / 从已有数据提取

2. **提问澄清** — 调查完毕后，基于提取到的信息，向用户提出所有疑问和不确定性。包括但不限于：
   - 复刻范围：哪些区域必须精确还原，哪些可以简化
   - 交互行为：按钮跳转、状态切换、弹窗、表单验证的具体逻辑
   - 数据来源：哪些字段是 mock、哪些对接真实 API、接口文档在哪
   - 状态差异：页面有几种状态（如竞价进行中/已结束），各状态的 UI 差异
   - 样式优先级：像素级还原 vs 功能优先、是否需要响应式
   - 路由和导航：页面间的跳转关系
   - 任何你不确定的细节

   **追问机制**：根据用户的回答继续追问，直到你有 **95% 以上的信息把握**理解用户的真实需求和目的。不要假设，不要猜，不确定就问。

3. **确认计划** — 输出完整计划文档（包括：复刻范围、技术方案、差异清单、注意事项），等用户确认后才开始动手
4. **实施** — 按计划逐项修改：布局容器 → 主色调 → 各组件 → 分页 → 响应式
5. **验证** — 编译检查 + 截图对比

## 约束

- **DOM 结构必须通过 eval 提取**，禁止仅凭截图推断布局结构
- 每个 CSS 值必须从 computed style 提取，禁止"看起来差不多"
- **未确认计划前禁止修改任何代码**
- 改完必须编译通过
- CSS 属性使用标准 kebab-case（`max-width`，不是 `maxWidth`）
- Vue 的 `v-show`/`v-if` 不能与 CSS 的 `display` 属性冲突
- 坑点速查见 [references/pitfalls.md](references/pitfalls.md)
- CDP 命令见 [references/cdp-cheatsheet.md](references/cdp-cheatsheet.md)
- 详细流程见 [references/method.md](references/method.md)

## 排除

- 不处理 JS 交互逻辑，只管样式
- 不负责接口对接
- 不修改路由/权限等非 UI 代码

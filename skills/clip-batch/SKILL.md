# Clip Batch — 批量消化积压

`clip-process` 的单篇版是给人用的：每一步都等用户拍板。
本 skill 是它的批处理版：**一次连跑 N 篇，全程不提问，跑完给一份报告。**

## 与 clip-process 的关系

| | clip-process | clip-batch（本 skill） |
|---|---|---|
| 篇数 | 一次 1 篇 | 一次 `--count` 篇（默认 3） |
| `## 入库思考` | **强制**，等用户回答 | **跳过**，写「（批量处理，未记录入库思考）」 |
| 用户交互 | 每步汇报、等继续 | 全程不提问 |
| 结尾 | 汇报单篇结果 | 追加批次记录到 `索引/消化记录.md` |

**除 Step 4 外，内容生成规则与 `clip-process` 完全一致**——需要细节就读那份，不在这里复述。

## 铁律

1. **不编造用户的思考。** `## 入库思考` 留空占位，不许替用户写「打动点」。编出来的思考比没有更糟：
   它会长成假记忆，以后 Reviwe/复习时会被当成自己写的。
2. **一篇一篇读完整。** 不许只看标题就生成常青笔记。读不完就跳过这篇，记进报告，不要硬写。
3. **没内容可炼就标废，不要凑字数。** 三句话的短帖硬写三条常青笔记，是在往知识库里灌水。
4. **宁可少炼，不要错炼。** 拿不准这篇讲了什么 → 跳过，记进「跳过」列表。批次报告里写清原因。

## 执行流程

### Step 1：取队列

```bash
cd /Users/chenjie/Documents/study/github/Obsidian
python3 工具/audit_vault.py --json
```

读 `stats` 确认分桶，读 `today` 拿前 N 条（`--count` 默认 3）。
**只处理 `today` 里的条目**——审计脚本已经排好优先级（最老的待炼在前），不要在队列外自己挑。

### Step 2：逐篇处理

对每一篇：

1. **读完整**（`wc -l` 后分段读，别只读前 60 行）
2. **判结构**（新版分节剪藏 / 小红书搬运稿 / 整理稿长文 / 普通卡片，处理方式同 `clip-process` Step 1b）
3. **判有没有料**：正文有效字 < 300，或通篇是清单/代码/TODO → **标废，跳过**，不生成内容
4. **搜关联卡片**：`grep -ril "关键词" 卡片/ --include="*.md"` 两三轮，读候选前 10-15 行确认
5. **写三节**（追加到文末，不动正文）：
   - `## 常青笔记` —— 1-3 条，小标题 + 2-3 句。**必须是不依赖原文也成立的洞见**
   - `## 连接` —— 已有卡片 `[[卡片名]]` 3-12 条（每条破折号说清关联点）+ 可建新卡片 `[[新名]]` 2-6 条
   - `## 行动` —— `- [ ]` 1-3 条，写真正会做的事
6. **打标记**：`tags` 加 `已整理`（原本是 `状态/未整理` 的改成 `状态/已整理`），`lastmod` 改成今天

`## 入库思考` 的写法（**不能省，也不能编**）：

```markdown
## 入库思考

> [!note] 批量处理
> 这篇由 clip-batch 自动消化，没有记录入库思考。如果它值得留，回来补一句「当时为什么剪它」。
```

### Step 3：写批次记录

追加到 `索引/消化记录.md`（不存在就新建，带 frontmatter `tags:` + `title: 消化记录`）：

```markdown
## YYYY-MM-DD · 第 N 批（共 M 篇）

| 篇目 | 结果 | 常青/连接/行动 |
|---|---|---|
| `路径` | 已炼 | 3 / 5+1 / 2 |
| `路径` | 标废跳过 | 原文过短，只有 180 字 |

**这批的一条**：[一句话说清这批里最值得记住的东西，没有就写「这批没有」]
```

### Step 4：报数

**不要逐篇复述内容**。只报：

- 处理了几篇、跳过几篇、剩多少待炼
- 明细写进 `索引/消化记录.md`，想看自己翻
- 如果这批里出现了**跟投资/写作直接相关**的洞见（比如一条能改选股逻辑的），单独提一句

## 成本纪律

批处理的 Token 成本主要来自两处，必须控制：

1. **不要把整篇长文回显到对话里**。读文件是为了理解，不是为了打印。
2. **不要跑完整审计的渲染**。用 `--json` 拿结构化数据，不要 `--apply` 重写积压报告（那是每天一次的事）。

一篇 6000 字的剪藏，正常应控制在 1.5–3 万 token 内完成。超过就说明哪里在重复读。

## 什么时候不该用

- 用户说「处理这一篇」 → 用 `clip-process`，他要参与
- 用户说「我今天想读点什么」 → 那不是消化，是阅读
- 待炼只剩个位数 → 手动炼完更好，批处理的价值在规模

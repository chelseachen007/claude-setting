`agent-autoloop tell <编号>` **必须带编号**，而且这个编号就是它要生成的卡片号：卡片 #71 的 facts 里
`{"type":"tell","changes":[{"table":"cards","key":"71",...}]}`，没有 `rule`、没有 `run`、也没有 `worker/runs/71-*` 目录。
也就是说 **tell 是「直接告诉人一件事」，用途是通知，不是派活给 Agent**——没人回答，也就没有 Agent 跑。

上一节写的「手动触发定时规则走不通」只是现象；根因是**告诉人 ≠ 派活**，两件事本来就不该混。
真要验证定时任务，只能直接跑技能本身，或者临时改 `when.cron` 在下一分钟触发。

### 中台模型名的精确结论（追一层对照实验）

上面写的「裸名走 xdpool」不够准。又做了一组对照，同一个 codex 只换 `-m`：

| `-m` | 结果 |
|---|---|
| `deepseek-v4.1-flash` 裸名 | ❌ xdpool 11128，codex 先警告 `Model metadata for \`deepseek-v4.1-flash\` not found. Defaulting to fallback metadata` |
| `deepseek-v4-flash` 裸名（config.toml 老默认） | ✅ 通（22,439 tokens） |
| `deepseek/deepseek-flash` 带前缀 | ✅ 通（168 tokens） |
| `deepseek/deepseek-v4-flash` 带前缀 | ✅ 通（166 tokens） |

**准确说法**：不是「所有裸名都错」，是**magpie 认不出的名字会被塞进 fallback 路由，fallback 落在 xdpool**。
判断方法：先看有没有那句 `Model metadata ... not found`。有 → 名字没注册，换名字；没有还失败 → 才是通道问题。

**规矩**：走 magpie 的地方模型名一律带上游前缀（`deepseek/`、`zhipu/`、`xd-pool-xdpool/`…）。裸名今天能跑，
明天换 provider 就可能又落进 xdpool。已写进 `~/ai/memory/projects/dsh-platform.md` 与 `projects/agent-autoloop.md`。

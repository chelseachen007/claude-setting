# 有数BI 公式编写助手

## 触发场景

用户在有数BI 中写计算字段、筛选器、参数默认值时遇到语法错误或逻辑问题。

## 核心知识

有数BI 的公式语法**不是 Excel、不是 SQL、不是 Tableau**，有自己的一套规则。详见 [references/syntax-cheatsheet.md](references/syntax-cheatsheet.md)。

## 工作流

### 第一步：信息收集（写公式前必须确认）

不要拿到需求就写公式，先确认以下信息，避免返工：

1. **字段类型**：字段是 String 还是 Date？决定用字符串函数还是日期函数
2. **枚举值**：涉及的每个字段的实际枚举值是什么？不猜，必须问用户确认
3. **字段歧义**：用户说的"问题状态"对应的是哪个字段？同一个概念可能有多个字段（如 `prblm_stat` 和 `rctfy_stat` 都可能被叫"状态"）
4. **计数口径**：
   - 统计"问题数" → 用问题编码去重
   - 统计"巡检单数" → 用巡检单ID去重
   - 分母是什么？全部记录还是筛选后的记录？
5. **复合指标**：如果是基于其他指标算的，先确认每个子指标的口径定义
6. **使用场景**：计算字段 / 筛选器 / 参数默认值 / 文本组件，不同场景语法要求不同
7. **组件类型**：用在图表还是文本组件？文本组件不继承图表筛选器，需要把筛选条件写进公式

### 第二步：写公式 → 用户粘贴测试 → 根据报错调整

## 高频错误速查

| 报错 | 原因 | 解法 |
|------|------|------|
| 表达式必须是已聚合状态 | 行级字段和聚合函数混用 | 外层包 MAX() 或 SUM() |
| 聚合粒度错误: 未聚合 vs 已聚合 | `=` 两侧聚合层级不一致 | 两侧都包 ATTR() 或 MAX() |
| 方法 LEFT 不能应用于 日期,整数 | 对 Date 类型用了字符串函数 | 改用 YEAR()/MONTH()/DAY() |
| 字段不存在: null | 任何地方写了 NULL 关键字 | 所有 NULL 都不能写，省略 ELSE/省略 IIF 第三参数 |
| 语法错误，缺少表达式 | 写了 CASE WHEN 条件 | CASE 只支持值匹配，条件用 IF/ELSE IF |
| ELSEIF 报错 | 关键词错误 | 是 `ELSE IF`（两个词），不是 ELSEIF |
| 分母为0 | 除法运算分母可能为零 | `IF SUM([分母]) = 0 THEN 0 ELSE 表达式` |
| DATEDIFF 参数错误 | 参数顺序写反 | `DATEDIFF("day", [开始], [结束])`，单位在第1参数 |
| COUNTD+IIF 聚合问题 | COUNTD 内嵌 IIF 在表格中不生效 | 用 `COUNTD(IIF(条件, [字段], ""))` 或改用 SUM+IIF 计数 |

## 常见场景模式

### 多状态分类（同一实体可同时属于多个状态）

❌ 错误：用 IF/ELSE IF 只会取第一个匹配的状态
✅ 正确：为每个状态建独立布尔标记（1/0），用 SUM 聚合

### 文本组件 vs 图表组件

文本组件**不继承**图表的筛选器上下文。解决：把筛选条件写进公式内部，而不是依赖外部筛选器。

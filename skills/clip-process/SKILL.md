# Clip Process — 剪藏深度处理

处理 `剪藏/` 目录中标记为 `状态/未整理` 的文章，补充闪念、常青笔记、连接和行动。

## 集成说明

本 skill 可由以下方式触发：
- **`clip-and-process` 自动调用**：用户选择深度处理时，路由器在提取+保存后调用本 skill
- **用户直接调用**：`/clip-process` 或说"处理剪藏"

能处理所有来源的内容：网页文章、图片平台 OCR 内容、视频转录文字稿、英文文章译文等。

## 职责边界

本 skill **只做深度处理**，读取已有剪藏文件，生成常青笔记、连接和行动。不提取内容、不保存新文件、不翻译。

## 触发词

- `/clip-process`
- "处理剪藏"
- "处理未整理的剪藏"
- "补充剪藏"

## 前提条件

剪藏文件必须满足以下格式：

```yaml
---
title: 文章标题
date: YYYY-MM-DD
tags: [剪藏, 状态/未整理]
---
```

且文件中已包含以下章节（由用户在浏览器中手动填充）：
- `## 总结` — 已有内容
- `## 金句摘抄` — 已有内容
- `## 原文` — 已有内容

## 执行流程

### Step 1：扫描未处理剪藏

1. 搜索 `剪藏/` 目录下所有 `.md` 文件
2. 筛选 frontmatter 中包含 `状态/未整理` 的文件
3. 如果有多个，列出文件名让用户选择要处理的文件
4. 如果只有一个，直接处理

筛选命令：
```bash
grep -rl "状态/未整理 剪藏/ --include="*.md"
```

### Step 2：读取文件内容

读取用户选定的剪藏文件完整内容，重点理解：
- 文章的核心主题和论点
- 用户已摘抄的金句（反映用户关注什么）
- 文章涉及的概念、方法、工具

### Step 3：排版预处理

在进入入库思考之前，先清理原文的排版问题。这一步自动完成，不需用户参与。

**处理范围**：仅处理 `## 原文` 章节内的内容，不动总结、金句摘抄等其他章节。

**执行方式**：运行预处理脚本：

```bash
python3 <skill目录>/preprocess.py "<剪藏文件路径>"
```

脚本自动完成以下处理：
1. **碎片化文字合并**：网页抓取导致的每字/标点独立一行 → 合并为正常段落，按句号断句分段
2. **加粗格式修复**：合并文字后产生的 `****` 错乱 → 恢复正确 `**text**` 格式
3. **连续空行合并**：超过 1 个连续空行 → 压缩为 1 个空行
4. **行首行尾空格清理**：每行去除首尾多余空格
5. **Markdown 标题修复**：`#` 后必须有且仅有一个空格，标题文字内部不允许有空格
6. **中文标点后多余空格**：中文标点后紧跟的空格去除
7. **frontmatter 修复**：`title` 字段内空格清理、tags 格式修正

脚本运行后，检查输出的行数变化（如 `原文 1219 行 → 118 行`），确认预处理效果。如果行数变化异常（如反而增多），检查文件格式是否符合预期。

### Step 4：入库思考（强制）

**这一步是强制的，不能跳过。不完成不入库。**

剪藏的前提是你已经看过并觉得有价值。在 AI 开始处理之前，必须先记录你自己的思考——AI 无法代替你完成这一步。

使用 AskUserQuestion 工具向用户提问：

> 你已经看过这篇文章并决定剪藏，说明它触动了你。请回答：
>
> 1. **最打动你的一点是什么？**（一个具体的点，不是"都挺好的"）
> 2. **跟你当下在思考/做的事情有什么关系？**（或者：为什么是现在剪藏它？）

将用户的回答写入文件的 `## 入库思考` 章节。如果文件中没有这个章节，在 `## 原文` 之后插入。格式：

```markdown
## 入库思考

> [!thought] YYYY-MM-DD
> **打动点**：[用户的回答 1]
> **当下关联**：[用户的回答 2]
```

**只有完成这一步，才继续后续的卡片搜索和内容生成。如果用户跳过，整个流程终止。**

### Step 5：搜索关联卡片

基于文章内容，在 `卡片/` 目录中搜索可能关联的已有卡片。搜索策略：

**第一轮：核心关键词搜索**
- 提取文章中 3-5 个核心概念关键词
- 在 `卡片/` 中搜索文件名和内容匹配

```bash
grep -ril "关键词1\|关键词2\|关键词3" 卡片/ --include="*.md"
```

**第二轮：主题扩展搜索**
- 基于文章主题扩展相关领域关键词
- 搜索方法论、工具、概念等维度

**第三轮：读取候选卡片**
- 读取搜索到的候选卡片的前 10-15 行
- 判断是否真正与文章内容相关
- 保留强关联的卡片（3-12 个）

### Step 6a：深度分析（先想清楚）

基于文章内容、用户入库思考和搜索到的关联卡片，输出一份**结构化分析**。这一步不生成最终内容，只做思考——先想清楚再写，质量比边读边写好得多。

分析输出格式（不写入文件，只在 Claude 的思考中完成）：

```
【关键实体与概念】
- 提取文章中的核心实体（人/组织/工具/方法）和核心概念（理论/框架/原则）

【与现有知识的连接点】
- 文章内容与搜索到的关联卡片之间的具体对应关系
- 每个关联卡片：文章的哪个部分与它有关、怎么关联

【知识张力与矛盾】
- 文章观点与 vault 中已有卡片观点的冲突或互补
- 文章填补了 vault 中的哪个知识空白

【用户入库思考的锚点分析】
- 打动用户的点，映射到哪些具体概念/卡片
- 用户的当下关联，暗示了什么行动方向

【内容生成建议】
- 建议生成几条常青笔记（主题预判）
- 最值得建的新卡片方向
- 行动项的优先级排序依据
```

### Step 6b：生成内容（基于分析）

基于 6a 的分析结果，生成以下章节。**以用户的入库思考为锚点**——打动用户的点应该在常青笔记和连接中得到呼应：

#### 闪念
**不生成**，保留为空由用户手动填写。

#### 常青笔记（1-3 条）
- 从文章中提炼的持久洞见
- 每条是一个独立的、面向未来的知识点
- 格式：小标题 + 2-3 句解释
- 不是总结文章，而是提炼"不管这篇文章存不存在，这个认知都有价值"的东西
- 优先覆盖 6a 分析中的"知识张力"和"用户锚点"

#### 连接 — 已有卡片（3-12 条）
- 每条用 `[[卡片名]]` 格式
- 每条后面用破折号简短说明关联原因（10-20 字）
- 只推荐真正相关的，宁缺毋滥
- 关联原因应体现 6a 分析中的具体连接点，不是泛泛的"主题相关"

#### 连接 — 可建新卡片（2-6 条）
- 每条用 `[[新卡片名]]` 格式（不存在的卡片）
- 每条后面说明为什么值得建以及建议内容方向
- 标准：文章中提到的有价值概念/方法，但 vault 中没有对应卡片
- 优先覆盖 6a 分析中指出的"知识空白"

#### 行动（1-3 条）
- 具体的、可执行的行动项
- 用 `- [ ]` 格式
- 只写真正会去做的事，不要写"深入学习"这种空话
- 优先级参考 6a 的"用户锚点分析"中的行动方向

### Step 7：写入文件

1. 用 Edit 工具将生成的内容填入对应章节
2. 将 frontmatter 中的 `状态/未整理` 改为 `状态/已整理`
3. 更新 `lastmod` 日期为当天

**重要**：只修改以下章节，不要动用户已有的 总结、金句摘抄、原文、Metadata：

```
## 入库思考      ← 用户已在上一步填入，不动
## 闪念          ← 不动，保留为空由用户手动填写
## 常青笔记      ← 填入内容
## 连接          ← 填入内容
## 行动          ← 填入内容
```

修改 frontmatter：
```
tags: [剪藏, 状态/未整理]  →  tags: [剪藏, 状态/已整理]
lastmod: 旧日期              →  lastmod: 今天日期
```

### Step 8：收录选题库（默认执行）

**默认自动收录到选题库**，除非用户明确说"不收录"。

根据文章内容自动判断分类（从以下标签中选最匹配的）：
- `健身` / `职场` / `AI` / `认知` / `方法论` / `投资` / `自媒体` / `心理` / `工具` / `生活` / `其他`

读取 `private/📋 选题库.md`，在对应章节添加条目：

**标题灵感**（如果原文标题写得好）：
```markdown
### 标题原文
- **来源**：文章名称或出处
- **地址**：原文 URL（从 frontmatter 或原文中提取）
- **打动你的点**：来自用户的入库思考
- **分类**：#标签
- **日期**：YYYY-MM-DD
```

**选题方向**（如果文章话题值得翻拍）：
```markdown
### 一句话描述选题角度
- **来源**：[[剪藏文件名]]
- **地址**：原文 URL
- **切入点**：基于入库思考的你的独特角度
- **适用平台**：小红书/公众号/视频
- **分类**：#标签
- **日期**：YYYY-MM-DD
```

**金句素材**（如果金句摘抄中有特别好的）：
```markdown
> 金句原文

- **来源**：文章名称
- **地址**：原文 URL
- **适用场景**：什么类型的内容可以用
- **分类**：#标签
- **日期**：YYYY-MM-DD
```

判断标准：
- **标题灵感**：标题有悬念/反差/数字/痛点，让你想点进去
- **选题方向**：话题本身值得用自己的角度重新讲一遍
- **金句素材**：独立成句，拿走就能用的表达

每篇剪藏至少收录一条（标题或选题），金句按需。用 Edit 工具追加到 `private/📋 选题库.md`。

### Step 9：输出结果

告知用户处理完成，简要报告：
- 处理了哪篇文章
- 找到几个已有卡片链接
- 建议几个新卡片
- 几条行动项
- 已收录到选题库（标题/选题/金句各几条，分类标签）

## 输出格式示例

```markdown
## 入库思考

> [!thought] 2026-04-15
> **打动点**：CLAUDE.md + Skills + MCP 三层架构让 AI 从工具变成工作系统
> **当下关联**：正在搭建自己的 Obsidian + Claude 工作流，直接可参考

## 闪念

（由用户手动填写，AI 不生成）

## 常青笔记

### AI 知识库的三层架构
CLAUDE.md（协作协议）+ Skills（工作手册）+ MCP（工具接口）。三层叠加让 AI 从工具变成工作系统，关键在于层与层之间的复利效应。

### 知识系统的飞轮
输入→处理→输出→进化，每个环节的产出都反哺其他环节，形成正向循环。

## 连接

### 已有卡片
- [[Claudian]] — Claude AI 集成到 Obsidian 的插件
- [[MCP]] — 文中用于连接外部工具的协议
- [[RAG]] — 知识库本质是给 AI 做 RAG

### 可建新卡片
- [[进化系统]] — 对比 AI 原稿和人类终稿的学习机制
- [[Skill 设计原则]] — 将工作流固化为可复用技能包的方法

## 行动
- [ ] 参考进化系统思路，在 skill 中加入修改对比功能
- [ ] 检查 CLAUDE.md 是否覆盖行为约束部分
```

## 注意事项

1. **不修改用户内容**：总结、金句摘抄、原文、入库思考、Metadata 由用户手动填写/确认，绝不修改
2. **不编造关联**：每个推荐的卡片链接必须通过实际搜索验证存在
3. **保持口语化**：闪念要像真实想法，不像论文摘要
4. **宁缺毋滥**：关联不确定的卡片不要放，宁可少推荐几个
5. **尊重现有格式**：如果用户的剪藏格式与模板有差异，按用户实际格式填充
6. **一次处理一篇**：每次只处理一篇，处理完确认后再处理下一篇

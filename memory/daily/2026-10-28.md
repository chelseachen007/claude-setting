# 2026-10-28

## 用 magpie 替换 CC Switch（模型网关迁移）

**结论**：四个客户端（Claude Code / Codex / Gemini CLI / DeepSeek Harness）全部改走 magpie 网关（`http://127.0.0.1:3425`），CC Switch 已退出、取消登录自启。CC Switch 安装未删，随时可回退。

### 安装与导入

- `curl -fsSL https://usemagpie.ai/install.sh | sh`，装到 `/Applications/magpie.app`（v0.1.1788）+ `~/.local/bin/magpie`；软链到 `~/.npm-global/bin/magpie`（PATH 里可用 `magpie`）。
- **magpie 启动时自动读 `~/.cc-switch/cc-switch.db` 导入 provider**，不需要手工导；导入后 8 个 provider。启动前 `magpie providers` 只会显示 no providers yet。
- 迁移前的库备份：`~/.config/magpie/backups/cc-switch-before-migration-20261028-090931.db`。

### 客户端接入口径（都是 magpie CLI 写配置，别手写）

| 客户端 | 命令 | 落点 |
|---|---|---|
| Claude Code | `magpie claude <provider/model>` | `~/.claude/settings.json` 的 `ANTHROPIC_BASE_URL=http://127.0.0.1:3425` + `ANTHROPIC_AUTH_TOKEN=magpie` |
| Codex | `magpie codex <provider/model>` | `~/.codex/config.toml` 的 `[model_providers.magpie]`（Responses `/v1`）+ `~/.codex/magpie-models.json` |
| Gemini CLI | `magpie gemini <provider/model>` | `~/.gemini/settings.json` 的 `model.name` |
| DSH | `magpie dsh <provider/model>` / `magpie dsh effort off` | `~/.dsh/profiles/web/cordis.patch.yml` 新增 `llm-pi-ai` 插件条目 |

### 踩过的坑（都是实测）

- **xdpool 只能给 Codex/DSH 用，不能给 Claude Code 用**：经 magpie 转发时 Claude Code 的流式请求必然报 `11128 Illegal API invocation from an unapproved channel`（workbuddy upstream），而同一模型的 curl 单发是 200。`magpie provider set ... user-agent=agent` 治不好。
- **Codex 模型目录不是自动的**：`magpie codex` 会重新生成 `~/.codex/magpie-models.json`，里面塞满不可用模型，需要手工裁。
- **Gemini CLI 0.59 必须开 `experimental.dynamicModelConfiguration`**：不开时 `isAutoModel()` 只认 `auto`/`auto-gemini-3`/`auto-gemini-2.5`，settings 里写的自定义模型名会被 `resolveModel()` 兜底成 `gemini-3.5-flash`，`--model` 参数也救不回来（`ModelNotFoundError: magpie knows no model "gemini-3.5-flash"`）。开了之后日志变成 `Selected model: deepseek/deepseek-v4-flash (Source: agent-router/override)`。
- **magpie 的 `library instructions` 会和 `~/ai/rules/global.md` 双写**：试过后回滚清空，全局规则仍只以 `~/ai/rules/global.md` 为唯一源；技能库同理不进 magpie（唯一源 `~/ai/skills`，55 个）。
- **dsh 的凭据**：`~/.dsh/.credentials.yaml` 的 refs 段加 `MAGPIE_GATEWAY_KEY: magpie`（网关不校验这个值），否则 pi-ai 插件抛 MISSING_CREDENTIAL。
- **dsh patch 文件语义**：同 id 的多个 patch 是浅覆盖不合并；`!delete` 之类自定义 tag 会直接让解析失败，删键只能整段重写。
- CC Switch 还留了个 LaunchAgent `io.ccswitch.deepseek-responses-sanitizer`（端口 15722），已 `launchctl bootout` 并把 plist 移到 `~/.config/magpie/backups/cc-switch-disabled/`。

### CC Switch 的关停动作

1. `osascript -e 'tell application "System Events" to delete login item "CC Switch"'` 去掉登录项；
2. `launchctl bootout gui/501/io.ccswitch.deepseek-responses-sanitizer` 卸载常驻代理；
3. 退出 App（网关 15721 已不再监听）。

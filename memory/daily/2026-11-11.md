### 教训

**「唯一源」不等于「唯一层」。** `~/ai/memory` 是做对了单一源，但没有分层——
所有东西平铺在 MEMORY.md，导致「每次都要知道」和「三个月用一次」抢同一份预算。
分层成本很低（一个索引表 + 三个档案文件），收益是每个会话省 1.2 万字节。

## GitHub 自动备份：把挂半年的 cron 换成 LaunchAgent

**发现根因**：旧 cron `0 12 * * * .../study/claude/cron-scripts/backup-to-github.sh` 从装上那天起就没成功过——
`backup.log` 里 146 条全是 `/bin/bash: ...: Operation not permitted`。macOS TCC 不给 cron 访问 `~/Documents`。
邪门的是 cron 每天 12:00 还在按时行刑，只是每次都行刑失败。脚本还备份早已卸载的 `~/.claude`。

**新建 `~/ai/scripts/vault-git-backup.sh`**：一次管 6 个仓库
（Obsidian、ai-assets[走 archive-ai.sh]、ObPublish、youtube、ai-image-automation、micro-web）。
- mkdir 原子锁 + 2 小时僵尸锁自清；日志 `~/ai/logs/vault-git-backup.log`，超 2MB 滚动
- **绝不 force push**；推前 `pull --rebase --autostash`，冲突就 `rebase --abort` 跳过该仓库
- 失败弹 osascript 通知，一个仓库挂了不影响其他

**新建 `~/Library/LaunchAgents/com.user.vault-git-backup.plist`**：每天 **12:30 和 22:30** 各跑一次。

## Obsidian 仓库瘦身 + 收尾

**257M → 45M**，用 `git filter-repo` 重写历史，三步剥离：
1. `.obsidian/copilot-index-*.json`（93MB 单文件）
2. `奔跑的小胖/`（旧笔记目录，含 3×44MB embeddings）、`附件/PDF/`（含 36.9MB PDF）、`*.mp3`、旧 `plugins/`
3. `.obsidian/plugins/*/main.js`（插件历史副本，能用 npm 重装）

笔记一篇没丢：卡片 1409 / 剪藏 560 / 投资研究 254 / 行思录 158 / private 110。
完整 .git 备份在 `~/Obsidian-full-backup-20261111-1738.tar.gz`（243M）。

**关键踩坑：`git pushurl` 会覆盖 `url`。** 只要配置里有 pushurl，push 就【只用 pushurl】，
url 仅供 fetch。上一轮我把它配成 `url=github, pushurl=gitee`，结果 GitHub 再也没被推送过——
而这种错误**不报错、不告警**，`git push` 返回成功。正确写法是两个都加到 pushurl：
`git remote set-url --add --push origin <github>` + 同样一条加 gitee。

**ObPublish submodule**：filter-repo 后旧 sha 失效，指针更新到新 HEAD，同时把 `.gitmodules`
的 `git@github.com:`（本机无 SSH key）改成 HTTPS，否则别处 clone 必失败。
发现 Vercel 每检测到 Obsidian 有新提交就自动推一个 `Update submodules`（远端已累积 82 个）。

**Obsidian Git 插件已关自动提交**：`autoSaveInterval`/`autoPushInterval`/`autoPullInterval` 全设 0、
`autoBackupAfterFileChange`/`autoPullOnBoot` 设 false，改前备份 `/tmp/obsidian-git-data.bak.json`。
理由：两个进程同时写同一个 .git 会撞 `index.lock` 并互相 rebase 打架。

2384 行 Next.js 代码只有一次 `Initial commit from Create Next App`，写的部分从没提交过。

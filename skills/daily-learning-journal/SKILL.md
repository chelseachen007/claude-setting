# 学习日记 & 周复盘助手

将 Claude Code 使用记录自动总结并写入 Obsidian 行思录。**周五自动触发周复盘模式。**

## 执行流程总览

```
┌─────────────────────────────────────────────────────────────┐
│                      主协调器                                │
│  Step 0: 检测星期几 → 周五？先写日复盘再周复盘 / 其他？日复盘  │
│  Step 0.5: 加载框架文件 + 状态文件（状态不存在则报错）         │
│  Step 1: 发现今日会话文件                                    │
│  Step 2: 用 Bash/grep/Python 串行分析每个会话（禁止并行agent）│
│  Step 3: 汇总所有结果                                        │
│  Step 4: 写入日复盘（含 AI 建议：A型详细 + B型一句话）        │
│  Step 5: (仅周五) 读取近7天日复盘，生成周复盘                  │
└─────────────────────────────────────────────────────────────┘
```

## ⚠️ 分析方式约束

**必须串行分析，禁止并行 Agent。**

原因：并行 Agent 会触发 API 速率限制（429），导致所有 agent 失败。

正确做法：
- 用 `Bash` 工具执行 `grep`/`python3` 命令直接提取会话信息
- 所有会话在一个 Bash 命令中批量分析（单个 for 循环遍历所有文件）
- 主协调器直接汇总结果，不委派给子 agent

## Step 0: 星期检测 & 模式分支

```bash
DOW=$(date +%u)  # 1=周一 ... 5=周五 ... 7=周日
```

**⚠️ 周几必须用 date 命令计算，禁止手写推断。** 生成周复盘面包屑表格时，每个日期的星期几都要用 `date -j -f "%Y-%m-%d" "$d" +%A` 计算，不要猜。

| `$DOW` | 模式 | 执行流程 |
|--------|------|---------|
| 5（周五） | **日复盘 + 周复盘** | 先完成当日日复盘 → 再读取近7天日复盘生成周复盘 |
| 其他 | **日复盘** | 正常日复盘 |

**用户可强制指定模式**：
- "周复盘" / "写周复盘" → 跳过日复盘，直接读近7天日复盘做周复盘（如果当日日复盘已存在）
- "日复盘" / "写日记" → 强制日复盘（即使周五也不做周复盘）

## Step 0.5: 加载框架与状态文件

**每次执行日复盘前，必须先加载以下两个文件：**

### 框架文件：`{VAULT_PATH}/private/🧠 高杠杆框架.md`

用 Read 工具读取。定义 A/B 型任务的输出标准和质量要求。

### 状态文件：`{VAULT_PATH}/private/🎯 当前状态.md`

用 Read 工具读取。包含用户的当前目标、本周焦点（`#重要性/A` `#重要性/B` 标记）和当前状态。

**⚠️ 如果状态文件不存在**：停止执行，提示用户先创建 `{VAULT_PATH}/private/🎯 当前状态.md`。参考模板：

**路径发现**：使用与日记路径相同的 VAULT_PATH 变量（见 Step 5）。先找到 vault 根目录，再拼接 `private/` 路径。

## 【日复盘模式】

### Step 1: 发现今日会话文件

**⚠️ 重要：必须按日期精确筛选，不能用 `-mtime 0`（那是过去24小时）**

```bash
TODAY=$(date +%Y-%m-%d)
for ROOT in ~/.dsh/sessions ~/.codex/sessions; do
  find "$ROOT" -name "*.jsonl" -not -path "*/subagents/*" 2>/dev/null
done | while read f; do
  mod_date=$(stat -f "%Sm" -t "%Y-%m-%d" "$f" 2>/dev/null)
  if [ "$mod_date" = "$TODAY" ]; then
    echo "$f"
  fi
done
```

### Step 2: 顺序分析每个会话

**逐个分析会话文件**，读取内容并提取关键信息。

**⚠️ 数量限制：如果会话超过 20 个，只分析最近 20 个**

**分析每个会话时提取：**

1. **用户主要意图** - 从前几条用户消息中提取
2. **使用的 Skills** - 搜索 `<command-name>/` 和 `<command-message>` 标签
3. **MCP 工具调用** - 搜索 `mcp__` 开头的工具调用，统计调用次数
4. **创建/更新的文件** - 搜索 `Write`, `Edit` 工具的 `file_path` 参数
5. **技术主题** - 识别 React, Vue, TypeScript, Python, Go, Docker, MCP, Agent, Hook 等关键词
6. **未完成事项** - 搜索 `[ ]`, `TODO`, `待办`, `未完成` 标记
7. **关键洞察** - 从对话中提取有价值的知识点
8. **项目路径** - 从 `cwd` 字段提取

### Step 3: 汇总所有结果

所有会话分析完成后，汇总提取的信息。

### Step 4: 汇总并生成日记

**汇总逻辑：**

1. **合并 Skills 使用** - 相同 skill 的 count 相加
2. **合并 MCP 工具** - 相同工具的 count 相加
3. **合并技术主题** - 去重
4. **合并文件操作** - 按笔记目录筛选，**但必须用 git log 验证**（见下方规则）
5. **合并未完成事项** - 去重
6. **提取关键洞察** - 选择最有价值的 3-5 条
7. **统计项目活动** - 按项目分组统计消息数
8. **生成"明日行动"建议** - 参照 Step 0.5 加载的框架文件和状态文件：
   - 从状态文件读取本周焦点（`#重要性/A` `#重要性/B` 标记）
   - 结合今日会话主题，判断哪些焦点有进展、哪些需要推进
   - A 型任务：生成具体 SOP + 话术/工具 + 备选方案
   - B 型任务：一句话懒人过关法
   - 如果今日活动与焦点无关，提醒校准
   - 拒绝泛泛之谈，每条建议必须可直接执行

**⚠️ 笔记列表准确性规则：**
- 「今日创建/更新的笔记」表格中的笔记，必须是 `git log` 或 `git diff` 中确认存在变更的文件
- JSONL 中出现的 `file_path` 可能只是被其他笔记 **链接** 了（作为 wikilink 目标），并非实际创建/更新
- 判断方法：用 `git log --since` 查看实际 commit 中变更的 md 文件，以此为准确数据源

## 【周复盘模式】

> ⚠️ 周复盘的前提：当日日复盘已写入。如果是周五，必须先完成日复盘再进入周复盘。

### Step 1: 读取近 7 天日复盘

周复盘的**唯一数据源**是近 7 天（含今天）的日复盘文件，不再重新分析原始会话。

```bash
# 计算近7天日期范围（含今天），同时输出正确的星期几
TODAY=$(date +%Y-%m-%d)
for i in $(seq 0 6); do
  d=$(date -v-${i}d +%Y-%m-%d 2>/dev/null || date -d "$i days ago" +%Y-%m-%d)
  YEAR=$(echo $d | cut -d- -f1)
  MONTH=$(echo $d | cut -d- -f1,2)
  # 用 date 计算星期几（macOS）
  DOW_NAME=$(date -j -f "%Y-%m-%d" "$d" +%A 2>/dev/null || date -d "$d" +%A)
  JOURNAL="行思录/日复盘/${YEAR}/${MONTH}/${d}.md"
  if [ -f "$JOURNAL" ]; then
    echo "$d $DOW_NAME: $JOURNAL"
  fi
done
```

**⚠️ 面包屑表格中的星期几必须使用上面脚本输出的 `$DOW_NAME`，不要手写推断。**

**如果日复盘不足 3 天**：提示用户本周日复盘数据不够，建议先补写缺失的日复盘。

### Step 2: 从日复盘中提取周维度数据

逐个读取日复盘文件，提取：

1. **每日面包屑** - 串联本周学习路径

5. **每日项目活动** - 汇总各项目进展

### Step 3: 生成周复盘

**周复盘汇总逻辑：**

3. **知识产出统计** - 本周新建卡片数、更新卡片数
4. **连接健康检查** - 本周新卡片中，有多少建立了 wikilink？有无孤立卡片？
5. **项目进展汇总** - 各项目本周推进了什么

## 会话分析方法（通用）

### JSONL 文件格式

会话文件为 JSONL 格式，每行一个 JSON 对象。**核心字段：**

```
type: "user"        ← 用户消息（不是 "human"）
type: "assistant"   ← AI 回复
type: "permission-mode"
type: "attachment"
```

**用户消息结构（type: "user"）：**
```json
{
  "type": "user",
  "message": {
    "role": "user",
    "content": "字符串" 或 [{"type": "text", "text": "..."}, {"type": "tool_result", ...}]
  },
  "cwd": "/项目路径",
  "sessionId": "xxx"
}
```

**content 可能是：**
- 字符串：直接文本内容（skill 命令如 `<command-message>xxx</command-message>`）
- 数组：包含 `{"type": "text", "text": "实际文本"}` 和 `{"type": "tool_result", "content": "工具返回"}`

**提取用户意图时需要过滤：**
- 跳过包含 `<command-message>` 的（是 skill 触发，不是用户意图）
- 跳过 `type: "tool_result"` 的（是工具返回结果）
- 只取 `type: "text"` 的实际用户文本

### 分析脚本

```bash
# 搜索关键模式
grep -c "command-name\|command-message" {session_file}  # Skills 使用
grep -o "mcp__[a-z_]*" {session_file} | sort | uniq -c  # MCP 工具
grep -o '"file_path":"[^"]*\.md"' {session_file} | head -20  # 笔记文件
grep -c '"type":"user"' {session_file}  # 用户消息数量
```

### 补充数据源：git log

文件变更信息用 `git log` 比 JSONL 更准确：

```bash
# 查看今日提交的文件变更
cd $VAULT_PATH
git log --since="YYYY-MM-DD" --oneline --name-only
```

### 提取规则

| 信息类型 | 搜索模式 | 提取方法 |
|----------|----------|----------|
| 用户意图 | `type: "user"` + `content` 中的 `type: "text"` | 取前 3 条，过滤 skill 触发和 tool_result |
| Skills | `<command-name>` | 统计出现次数 |
| MCP 工具 | `mcp__` 前缀 | 提取工具名并计数 |
| 文件操作 | git log + JSONL `file_path` | 优先 git log |
| 技术主题 | 关键词匹配 | React, Vue, Python 等 |
| 未完成 | `[ ]`, `TODO` | 提取整行 |
| 项目路径 | `cwd` 字段 | 提取目录名 |

## 性能优化

1. **限制数量** - 如果会话超过 20 个，只分析最近 20 个
2. **增量分析** - 可选只分析新增内容

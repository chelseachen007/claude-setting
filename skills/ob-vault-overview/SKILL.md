# Vault Overview — 知识地图生成

扫描 Obsidian vault 的卡片连接关系和目录结构，生成结构化知识地图到 `索引/知识地图.md`。

借鉴 LLM Wiki 的图谱洞察思路，用 Dataview + grep 分析替代图算法，发现知识枢纽、孤立页面和主题聚类。

## 触发词

- `/vault-overview`
- "更新知识地图"
- "生成知识地图"

## 输出文件

`索引/知识地图.md`

## 执行流程

### Step 1：扫描 vault 统计数据

用 Bash 命令收集基础数据：

```bash
# 各目录文件数
for dir in 卡片 剪藏 读书记录 行思录/日复盘 产出文章 视频学习 洞察报告; do
  count=$(find "$dir" -name "*.md" 2>/dev/null | wc -l)
  echo "$dir: $count"
done

# 总卡片数
find 卡片/ -name "*.md" | wc -l

# 本周新增（最近7天）
find 卡片/ -name "*.md" -mtime -7 | wc -l
```

### Step 2：发现知识枢纽（被引用最多的卡片）

扫描所有 `[[wikilink]]` 提及，统计被引用次数 Top 20：

```bash
# 提取所有 wikilink 并统计频率
grep -roh '\[\[[^]]*\]\]' 卡片/ 剪藏/ 读书记录/ 产出文章/ --include="*.md" | \
  sed 's/\[\[//;s/\]\]//' | sort | uniq -c | sort -rn | head -20
```

这些是知识网络的枢纽节点——最多其他卡片指向它们。

### Step 3：发现孤立页面

找出没有任何 `[[wikilink]]` 指向它、它也没指向别人的卡片：

```bash
# 获取所有卡片名（不含扩展名）
ls 卡片/ | sed 's/\.md$//'

# 获取所有出现的 wikilink
grep -roh '\[\[[^]]*\]\]' 卡片/ 剪藏/ --include="*.md" | sed 's/\[\[//;s/\]\]//'

# 差集 = 孤立页面
```

孤立页面 = 没有被任何 `[[wikilink]]` 引用的卡片（且卡片自身也没有 wikilink）。列出所有孤立页面，最多显示 30 个。

### Step 4：主题聚类

通过共同引用关系发现主题聚类。方法：

1. 找出每个卡片引用了哪些其他卡片
2. 引用了相同卡片的卡片归为一类
3. 用 LLM 给每个聚类命名

实际执行时，先获取枢纽卡片（Step 2 的结果），然后找出哪些卡片引用了同一个枢纽卡片——这就是最简单的"共同引用聚类"。

对每个枢纽卡片，列出引用它的卡片列表（最多 10 个）。用 LLM 判断这些卡片是否形成有意义的主题聚类，如果是，给出聚类名称和简述。

### Step 5：知识盲区

分析发现三类知识盲区：

**孤立页面**（来自 Step 3）：列出卡片名，这些是还没融入知识网络的点。

**稀疏主题**：主题聚类中卡片少于 3 个的领域，说明这个主题才开始积累。

**桥接卡片**：被 3 个以上不同主题聚类的卡片引用的卡片。它们是连接不同知识领域的桥梁。

### Step 6：写入知识地图

将分析结果写入 `索引/知识地图.md`，格式如下：

```markdown
---
tags:
title: 知识地图
date: YYYY-MM-DD
lastmod: YYYY-MM-DD
---

# 知识地图

> 自动生成于 YYYY-MM-DD，上次更新于 YYYY-MM-DD
> 下次更新：当你觉得卡片量有明显变化时，运行 `/vault-overview`
```

### Step 7：输出摘要

告知用户：
- 知识地图已更新
- 关键发现：最大的主题聚类、最需关注的盲区
- 建议：哪些孤立页面值得优先建立连接

## 注意事项

1. **不修改任何现有文件**，只生成/更新 `索引/知识地图.md`
2. 孤立页面不等于"没有价值"，只是还没建立连接
3. 聚类基于 `[[wikilink]]` 引用关系，不分析内容语义
4. 如果 vault 很大（>2000 卡片），统计可能需要几十秒
5. 每次运行完全覆盖 `索引/知识地图.md`

# 方法.md — 补贴-基站新能源AI医药-20261111

> 这份文件回答「当时怎么做的、数字怎么算的、哪几条没核实」。正文见 [研究.md](研究.md)。

## 一、研究问题

用户原话（2026-11-11）：「大力发展基站，到新能源补贴，ai补贴，再到现在的医药，只能说哪里补贴最足就去哪里，吃的可不止一点半点。」

核心假设：**补贴强度与板块涨幅正相关**。本研究要做的是证伪/证实这个假设。

## 二、做了什么

1. **政策线**：拆成三组并行调研
   - 新能源（子 agent）：补贴退坡时间表、反内卷政策、价格与产能数据
   - 基站 + AI（子 agent）：补贴金额、运营商 CAPEX、AI 补贴的流向
   - 医药（子 agent）：中央投资、支付端政策、集采
2. **行情线**：东财板块日线，自算五个阶段的涨幅矩阵
3. **财务线**：全市场三期财报（2025三季报 / 2026中报 / 2026三季报）+ 现金流 + 资产负债
4. **交叉验证**：补贴金额 vs 板块涨幅 vs 毛利扩张 vs 经营现金流

### 3.2 口径定义（重要，别混）

**PE**：全部用**静态 PE**（2025 年报口径），标注为 `PE25A`。不是 TTM。
- 原因：2026 年利润爆发，TTM 和静态能差 3 倍，静态是唯一能横向比较的口径
- 简化年化：用「2026 前三季 × 4/3」，这只是粗估，不是严格 TTM

**毛利率**：
- 累计毛利率 = 东财 `XSMLL` 字段
- 单季毛利率 = (Q3累计营收 × Q3累计毛利率 − H1营收 × H1毛利率) / (Q3营收 − H1营收)
- 全 A 加权 = 按营收加权（不是简单平均）

**OCF（经营现金流）**：东财 `NETCASH_OPERATE`，单位元，报告里换算成亿。

**板块涨跌**：东财板块指数（BK 码）自算区间涨幅。
- 与申万、同花顺口径差 10%~30%
- 与另一子 agent 自算的 CPO 2025 涨幅差 56pp（我 +163.4% vs 它 +107.2%），原因是基准日不同：我取 2024-12-31 收盘，它取 2024 年末某日
- **本报告统一用我的口径**

**距高点**：从 2025-01-01 起算的区间最高价，不跨年。

### 3.3 关键技术处理

- **绕过本机代理**：`urllib.request.ProxyHandler({})`，否则东财接口全部 502
- **PE 精度**：`f162` 返回 ×100 整数，要 /100
- **财报接口列名**：`RPT_LICO_FN_CPD` 不能写 `NOTICE_DATE` / `DEDUCT_PARENT_NETPROFIT` / `OPERATE_INCOME`
- **现金流量表 filter**：用 `REPORT_DATE='2026-09-30 00:00:00'`，不是 `REPORTDATE`

## 五、不确定项（需要后续核实的）

按重要性排序：

1. **政策文号与金额全部未回原文核对**。本次研究没用 web_search，政策内容来自三个子 agent 的检索结果。以下需要去 gov.cn 原文核实：
   - 136 号文（发改价格〔2025〕136号）
   - 国办发〔2026〕9 号
   - 工信部联规〔2026〕216 号 / 210 号
   - 发改委强基工程 200 亿、三批 312.94 亿
   - 深圳 5G 基站奖补标准
2. **「全国算力券破 10 亿」来自自媒体转载**，可信度低，只作量级参考
3. **光伏主材板块（BK1318）只有 2 只成分股**，涨跌不代表整个主材板块
4. **储能地方补贴未逐一核实**
5. **东财板块 PE 取的是当日盘中数据**，与收盘后计算差 ±0.1~0.5

## 六、如果重做，哪里可以更快

- 政策调研应该先自己用 web_search 核对关键文号，再派子 agent 深挖，而不是全部外包
- 财报三期的合并应该一开始就写进 `fetch_eastmoney.py`，避免 40 个一次性脚本
- 单季毛利的推算公式应该标准化（现在的公式在营收环比下滑时会失真，报告里没有处理这个边界）

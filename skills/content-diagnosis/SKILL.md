# 内容诊断 — 发布前策略健康检查

## 职责

本 Skill 是发布前的内容策略诊断工具。**不检查写作质量**（那是 `pang-writer` L1-L4 的活），而是检查内容策略：这篇内容是否代表了正确的 IP、是否连接了正确的产品、是否触动了正确的情绪。

## 触发条件

- 用户说"诊断"/"内容诊断"/"发布前检查"/"能不能发"/"帮我看看这篇"
- 用户完成一篇内容准备发布前
- `content-factory` 流水线中的发布验证环节

## Pre-flight

诊断前先读取以下文件作为参考基准：
1. `private/🎭 小胖素材库.md` — IP 辨识度的对比基准（内容是否用了素材库中的素材？）
2. `pang-writer` 的禁用词列表和风格指南 — AI 味检测的参考规则

## 六维度诊断

### 1. IP 辨识度（权重最高）

**核心问题**：删掉署名，读者知道这是小胖写的吗？

检查项：
- 是否使用了素材库中的标志性主题？（AI 民主化、亲自下场、信息差）
- 是否有只有小胖才会写的角度或表达？
- 文章的写作基因是否可识别？（句式断裂、文化升维、人物画像法）
- 换成另一个 AI 博主的名字，文章还成立吗？如果成立，IP 辨识度不够

**评分**：0-10
- 8-10：高度可辨识，有明确的个人印记
- 5-7：有些辨识度，但不够突出
- 0-4：通用内容，换个名字一样成立

### 2. 真人感

**核心问题**：读起来像真人的声音吗？

检查项：
- 是否有第一人称亲身经历？（不是"有人做过实验"，是"我亲自去做了"）
- 是否有情感脆弱或自我暴露？
- 是否有具体的细节（数字、名字、时间、地点）而非模糊描述？
- 是否有口语化的情绪表达？（"。。。"、"？？？"、"= ="）

**评分**：0-10

### 3. 产品桥梁

**核心问题**：读者看完会想了解你的什么吗？

检查项：
- 内容是否自然地展示了专业度？（不是硬推产品，是让读者觉得"这个人很专业"）
- 是否有从内容到产品的自然过渡？（素材库中"产品桥梁"分类的用法）
- 是否有延伸钩子？（"完整的流程我整理在了..."）
- 过渡是否生硬？生硬的推销比没有推销更糟

**评分**：0-10，外加"桥梁是否存在"判断

### 4. 情绪路径

**核心问题**：读者的情绪旅程是经过设计的还是随机堆砌？

检查项：
- 开头是否抓住了情绪？（好奇/共鸣/惊讶/荒诞）
- 中间是否有情绪变化？（不是持续平铺的信息输出）
- 是否有情绪高点？（"卧槽"时刻）
- 结尾是否有情绪释放？（回环呼应/哲思余韵/信念宣言）
- 整体情绪弧线是否连贯？

**评分**：0-10，外加识别出的情绪弧描述

### 5. AI 味检测

**核心问题**：是否有 AI 写作的典型痕迹？

检查项（在 L1 禁用词之外）：
- 是否有不自然的对称结构？（"一方面...另一方面"）
- 是否有过于均衡的论证？（每个观点都给了正反两面，缺乏立场）
- 是否缺少具体名字？（用"某个工具"而非"Claude Code"）
- 是否有过于流畅的过渡掩盖了真实声音？
- 推荐口语化词组是否被自然使用？
- 段落节奏是否过于均匀？（真人写作节奏天然有波动）

**评分**：0-10
- 8-10：几乎无 AI 味
- 5-7：偶有 AI 痕迹但不明显
- 0-4：AI 味明显，需要重写

### 6. 合规检查

**核心问题**：有没有可能被封号/限流/投诉的风险？

检查项：
- 是否有具体收入数字？（小红书/公众号可能触发审核）
- 是否有"躺赚"等违规话术？
- 是否有未经证实的对具体公司/人物的负面评价？
- 是否有付费转化的直接引导？（各平台对引流管控不同）
- 图片/截图是否包含隐私信息？（微信号、手机号等）

**评分**：✅ 通过 / ⚠️ 警告 / ❌ 必须修改

## 输出格式

```
## 内容诊断报告

**诊断时间**：YYYY-MM-DD HH:mm
**内容类型**：公众号长文 / 小红书笔记 / 视频脚本 / 其他
**字数**：XXXX

### 综合评分：XX / 60

| 维度 | 分数 | 状态 | 关键发现 |
|------|------|------|---------|
| IP辨识度 | X/10 | 🟢/🟡/🔴 | 一句话发现 |
| 真人感 | X/10 | 🟢/🟡/🔴 | 一句话发现 |
| 产品桥梁 | X/10 | 🟢/🟡/🔴 | 一句话发现 |
| 情绪路径 | X/10 | 🟢/🟡/🔴 | 一句话发现 |
| AI味检测 | X/10 | 🟢/🟡/🔴 | 一句话发现 |
| 合规检查 | ✅/⚠️/❌ | — | 一句话发现 |

### 修复建议（按优先级）

1. **[最严重的问题]**：具体描述 + 修改建议
2. **[次严重的问题]**：具体描述 + 修改建议
3. **[改进建议]**：具体描述 + 修改建议

### 发布建议
✅ 可以发布 / 🟡 建议修改后发布 / 🔴 需要重大修改
```

状态阈值：
- 🟢 8-10 分（合规为 ✅）
- 🟡 5-7 分（合规为 ⚠️）
- 🔴 0-4 分（合规为 ❌）

综合评分：
- 50+ 且合规通过 → ✅ 可以发布
- 40-49 或有 ⚠️ → 🟡 建议修改后发布
- <40 或有 ❌ → 🔴 需要重大修改

## 使用方式

### 独立调用
```
/content-diagnosis
```
然后粘贴内容或提供文件路径。

### 在写作流程中使用
完成 `pang-writer` L1-L4 质检后，发布前调用本 Skill 做策略层诊断。

### 在 content-factory 中使用
作为流水线的发布验证步骤，在 `multi-publish` 之前执行。

# 2026-11-01

## WorkBuddy 会话全量导入 DSH（`/import-all workbuddy`）

**结论**：WorkBuddy 国内版（`~/.workbuddy`）+ 国外版（`~/.workbuddy-ai`）共 127 个会话现在全在 DSH 里，注册表 0 缺口。过程中发现并修了插件一个真 bug。

### 数字

- 国内版 10 个（9 新增 + 1 之前已导），国外版 117 个（其中 86 个历史上已导，24 个新增）。
- 本轮实际新建 32 个 DSH 会话，0 失败、0 降级（无图片降级、无未归组）；1 个按墓碑跳过（`archived`）。
- 新建 5 个工作区分组，其余复用已存在的 cwd 工作区。

### 根因 bug：0.26.2 的 workbuddy 扫描器自拒 `-ai` 路径

`lib/discovery/claude.mjs` 的 `scanWorkbuddy` 用 `\.workbuddy[\\/]projects` 做路径签名自拒，但**同一个文件里的 `roots()`、`matchFile`、`workbuddyLayoutProject` 都放行了 `(-ai)?`**——只有扫描器这一处漏了。后果：`~/.workbuddy-ai/projects` 下 110 个会话在面板和 `/import-all` 里**完全不可见**，而 `scan` CLI（`lib/scan-cli.mjs` 另有一份实现）却能扫到 127 个，两边数字对不上。

已就地改成 `\.workbuddy(-ai)?[\\/]projects`，并验证该模块直接调用能扫出 127 条。

**教训**：同一个来源的路径签名在同一个文件里出现了 4 次（roots / matchFile / layoutProject / 扫描器自拒），其中只要有一处漏掉可选项，症状就是「静默少了半个来源」。`npx dsh-chat-import scan workbuddy` 与面板数字不一致时，先怀疑这类副本分叉。

### 绕开发现层的做法（面板扫不到时的应急通道）

面板/发现层扫不到，不等于导入管线不能用——`POST /api-import/import` 直接吃 `items: [{ source, sourcePath, sessionId }]`，不经过 `scanWorkbuddy`，所以能导。token 从 `~/.dsh/web.out` 最后一行的 `dsh web: http://127.0.0.1:3080/?token=...` 取。

**注意**：改 `node_modules` 里的插件代码后，运行中的 web 进程仍用旧模块（ESM 已缓存），要重启 dsh web 才生效；数据已落盘的部分不受影响。

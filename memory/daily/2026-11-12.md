## 减负计划 D：会话考古（首次，已定位根因）

写了 `~/ai/invest/工具/session_archaeology.py`，只统计**人说的话**（第一版统计命令频次是错的，
那挖出来的是 agent 自己的重复劳动，不是人的负担）。

**核心发现：您手动敲的「继续」不是催我，是在替一条单点模型路由做人工容灾。**

- 本机会话 437 个（另 205 个导入的旧会话单独统计）。重复原话：继续 49 次、请继续执行任务 10、重试 9、
  只回复两个字：通了 7、你好 6、提交代码 5、模型调用失败了看下问题 4。
- 本机会话里 36 次「继续」**100% 出现在 `turn/end` 且 `reason.kind="error"` 之后**，没有一次是任务完成或等确认。
- `turn/end` 原因：completed 779 / error 37 / aborted 30 / interrupted 22。
- error 细分：**429 限流 21 次**、502 传输 6、400 非法 3、403 账号被关 1。出错模型 deepseek-v4.1-flash 11 次、kimi-k3.1-pro 10 次。
- 为什么重试救不回来：DSH 默认 `maxRetries:5` + 退避 500ms→10s，**总窗口仅约 15.5 秒**；
  而 429 原文是 `1/1 cooling`（只有一个账号，冷却期为分钟级）。
- 为什么只有一个通道：只有 neko-api（余额不足）和 xdpool（拒绝 Codex 指纹，报 11128）提供 v4.1-flash。

**已修**：`~/.dsh/profiles/web/cordis.patch.yml` 给两个 magpie provider 加 retryPolicy——
`maxRetries:12`、`initialDelayMs:2000`、`maxDelayMs:120000`、`jitterRatio:0.2`，总窗口约 10 分钟以上。
`dsh --profile web --dump-config` 校验通过（exit 0）。**需重启 dsh web 生效。**

**顺带查到的账**：`magpie quotas` 显示 DeepSeek 官方余额 **¥5.09**（10-28 是 ¥9.09，14 天只花 ¥2.8）——
最便宜最稳的官方通道这半个月几乎没被用上，请求大量撞在 neko/xdpool 上报错重试。
**这件事该您决定：要不要给官方充值。**

报告落在 `Obsidian/索引/会话考古-2026-11-12.md`（commit 57a5a772）。

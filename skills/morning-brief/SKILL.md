# 晨间一条决策

## 这个技能要解决什么

早报不是报告，是**替你做完今天第一次判断**。产出只有一个标准：
读完那一条推送，你知道今天做什么（或者明确知道今天什么都不用做），不需要再去翻任何文件。

反面教材是 2026-11-11 那版：三段式「最近发生了什么 / 今天该做什么 / 要留意什么」，
「今天该做什么」写的是「先确认雪球采集连接」「逐条核查 T1–T7」——把活派回给用户。
这版起废掉这种写法：**你脑子里的判断，不写给人；你拿不准的，也不写给人。**

## 铁律

1. **「今天该做」只能有一条，而且是决定，不是待办。**
   好：「海尔智家进候选池，今天我不动，等回撤到 25% 再说」
   坏：「核查海尔智家的估值」「关注雪球有没有提到它」
2. **矛盾要你自己消解。** 数据源之间打架（日报说 T1 命中 / 盯盘说没到），
   你先查一手口径，得出一个结论写进去；查不实就把那一条降级为「不能作为依据」并说明原因。
   **绝不把两个互相矛盾的结论并列摆给人，那等于把矛盾退货给他。**
3. **没信号就是今天最省脑子的结论。** 一天没有任何事情要处理，是正常且值得高兴的结果。
   不要为了把早报写满而制造话题。
4. **只写他看得懂的影响。** 每个判断后面接一句「对你意味着什么」，不写过程、不写口径表格、不写方法论。
5. **不替人下单，也不编造没发生过的事。** 动作写成「什么价格、多少股、上限多少钱、等不到就不买」，
   而不是「买入 300 股」。文件的时间戳、脚本做过什么，你没亲眼看过的就不要写进「依据」——那是编的。

## 步骤

### 1. 幂等
目标文件 `行思录/早报/YYYY-MM-DD.md`（月份补零）。已存在就不重写，第一行输出「没事可做：今天的早报已经写过了」结束。
不要碰 `行思录/日复盘/`。

### 2. 先跑机器，再读人写的
按这个顺序取事实，**机器结论优先于人写的叙述**：

```bash
# ① 盯盘：关注池 + T1–T4 + 碳酸锂，这是唯一可信的"触发器到没到"的答案
cd ~/ai/invest && .venv/bin/python3 工具/盯盘/盯盘.py --json
```
- `fired` 里 `kind=actionable` → 真信号，进决策
- `already_reported: true` 只代表「今天已经弹过通知」，**不代表这事过去了**，照样要进决策
- `kind=state_change` → 进「今天要知道」
- `errors` 非空 → **明确写出哪个源坏了**，别假装数据是全的

```bash
# ② 雪球日报：按【文件名里的日期】取最新，不要用 ls -t
#    mtime 会被迁移、批量改写脚本污染（2026-11-12 就有个 8 月的文件 mtime 是今天）
ls ~/ai/invest/素材/雪球日报/*.md | grep -oE '[0-9]{4}-[0-9]{2}-[0-9]{2}' | sort -r | head -1
```

- 拿到日期后**先对比今天**。差超过 3 天 → 在「依据」里写明「雪球日报停在 X 月 X 日，今天没有」，不许拿旧日报当今天的论据
- 日报里的叙述可以参考，但它对触发器的判定不可信（2026-11-11 那次就把 T1 判错了），触发器只认盯盘
读它的「今日亮点」和「今日三问」，但只采信它的**叙述**（大佬在吵什么、什么被反复提），
**不采信它对触发器的判定**——那一步以盯盘为准。

```bash
# ③ 本地最近的动静（不联网）
find . -type f -mtime -3 -not -path './.git/*' -not -path './node_modules/*' \
  -not -path './.obsidian/*' -not -path './.workbuddy-ai/*'
git log --since=3.days --oneline      # 是 git 仓库才跑
```
从里面找**没收尾的东西**：写着「待核对」「TODO」「未验证」「下一步」的笔记、
停在初稿的研究、连续几天没动的线程。这些是 C/D 线要接的活，今天最多挑一件。

### 3. 算一个决定
按优先级自上而下取第一个成立的：

| 顺序 | 条件 | 决定 |
|---|---|---|
| 1 | 盯盘有 actionable | **给出前提条件式的动作**，不替人下单。写清触发价、股数、金额上限，以及「等不到就不买」——决定是「做什么」，不是「已经做了」 |
| 2 | 数据源坏了 | 今天先修源，并说明断了几天的数据会怎么影响判断 |
| 3 | 有明确的时间锁（财报日、政策落地日、几天后的会） | 记下日期，今天不动 |
| 4 | 有停更太久的线程（>7 天没动且属于他自己的东西） | 今天推进它，或者明确宣布放弃 |
| 5 | 都没有 | **今天什么都不用做** |

### 4. 写文件
`行思录/早报/YYYY-MM-DD.md`，frontmatter 与旧版一致（tags/title/date/lastmod）。
正文**只有四节**，按顺序，能省就省：

```markdown
# 早报 2026-11-12

## 今天就做这一件
一句话。是决定，带价位/金额/时间。或者明确写「今天什么都不用做」。

## 今天要知道的
最多三条。每条一句，带一句「意味着什么」。
只放会影响判断的东西：真信号、数据源故障、时间锁、他持有的票的异动。
没有就写「没有」。

## 别被带走
最多两条。市场噪音、别人的热闹、和他无关的热点。
目的是提前把「不需要理的事」说清楚，省掉他自己判断的那一步。

## 依据
- 盯盘：<路径或"跑了，无信号">
- 雪球日报：<最近一份的文件名>
- 其他：<改动的笔记/提交>
```

### 5. 推送
最后一条消息的**第一行**写「今天就做这一件」那句话，后面跟文件路径。
一句话说完，不附回执、不复述标题、不写「以上是今天的早报」。

## 什么时候该怀疑自己

- 你写的「今天就做这一件」里出现了「确认」「核查」「检查」「关注有没有」→ 你在派活，改掉
- 你写了超过一条决定 → 你在逃避排序，回去重新比较优先级
- 你写了三段以上的「要知道」→ 你在把日报搬过来，砍掉
- 你没法给出价位/金额/日期 → 说明这个决定还没算清楚，那就归到「今天什么都不用做」并写清理由

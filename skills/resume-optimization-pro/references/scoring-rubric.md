# 简历评分标准（Resume Scoring Rubric）

## 评分体系概览

总分100分，分为8个维度：

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 信息准确性 | 15分 | 所有数据可验证，无虚构夸大 |
| 结构合理性 | 15分 | 层次清晰，重点突出，篇幅适中 |
| 专业表达 | 15分 | 符合岗位级别，用词精准 |
| 框架应用 | 10分 | CAR/STAR原则贯穿 |
| 量化数据 | 10分 | 业绩/规模/效率均量化 |
| 差异化竞争力 | 15分 | 独特价值主张清晰 |
| ATS友好度 | 10分 | 关键词覆盖，格式规范 |
| 细节完善度 | 10分 | 无冗余、无遗漏、无错误 |

---

## 1. 信息准确性（15分）

### 评分标准

- **15分（优秀）**：所有信息真实可验证，数据一致性100%，无任何虚构或夸大
- **12分（良好）**：核心信息真实，有1-2处轻微表述偏差，不影响整体真实性
- **8分（及格）**：大部分真实，有3-5处夸大或不准确表述
- **5分（不及格）**：存在明显虚构内容或重大数据矛盾
- **0分（严重）**：大量虚假信息，严重误导

### 检查清单

- [ ] 工作年限准确（与工作经历时间一致）
- [ ] 数据一致性（同一数据在不同位置表述一致）
- [ ] 项目数量可验证
- [ ] 团队规模准确
- [ ] 业绩数据真实
- [ ] 资质认证有效（未过期）
- [ ] 荣誉奖项真实
- [ ] 技术能力不夸大

### 常见问题

❌ **虚构内容**：
- "填补国内XX空白"（绝对化表述）
- "首创XX技术"（无法验证）
- 项目数量夸大（实际XX个写成YYY个）

❌ **数据矛盾**：
- 工作经历显示5年，专业概述写"近10年经验"
- 团队规模不一致（一处写X人，另一处写Y人）
- 时间线矛盾（项目时间重叠或超出在职期）

✅ **正确示例**：
- "拥有近10年行业从业经验"（与工作经历时间一致）
- "年度业绩XX万+"（可验证的具体数据）
- "团队获得行业竞赛第一名"（有证书证明）

## 2. 结构合理性（15分）

### 评分标准

- **15分（优秀）**：层次清晰，信息分布合理，篇幅控制完美（技术总监2页）
- **12分（良好）**：结构清晰，略有冗余或遗漏，篇幅略长/短
- **8分（及格）**：结构基本合理，但有明显冗余或重要内容埋没
- **5分（不及格）**：结构混乱，重点不突出，篇幅严重不合理
- **0分（严重）**：完全无结构，信息杂乱无章

### 标准结构

**技术总监/管理岗位**（推荐顺序）：
1. 联系方式
2. 专业概述（2-3句话，核心价值）
3. 核心技能（4-6个分类）
4. 工作经验（倒序，2-3个核心岗位）
5. 荣誉奖项（5-8项）
6. 教育背景

**篇幅标准**：
- 0-5年：1页
- 5-10年：1-2页
- 10年+：2页（最多3页）

### 检查清单

- [ ] 节标题层次清晰（一级/二级/三级）
- [ ] 重要信息优先展示
- [ ] 无大段文字（每段≤5行）
- [ ] 成就用bullet points展示
- [ ] 篇幅控制在标准范围内
- [ ] 无重复内容
- [ ] 无"备份"等无用章节

### 常见问题

❌ **结构问题**：
- 工作经验放在核心技能之前（管理岗位应突出能力）
- 每个岗位都详细描述（应聚焦核心岗位）
- 项目单独成节（技术总监应整合到工作经验中）

❌ **篇幅问题**：
- 10年经验写7页（严重冗余）
- 管理岗位写单页（信息不足）
- 大段文字无分段（阅读体验差）

✅ **正确示例**：
```markdown
### 某公司 | 技术总监 | YYYY.MM - 至今

**管理成就**：
- 从0到1组建N人团队...（成就1）
- 推动公司品牌能力提升...（成就2）
- 主导某核心产品...（成就3）

**核心产品**：
#### 某产品名称
- **产品定位与价值**：...
- **关键决策**：...
```

## 3. 专业表达（15分）

### 评分标准

- **15分（优秀）**：完全符合岗位级别，用词精准，视角准确
- **12分（良好）**：大部分符合，有1-2处表述不够精准
- **8分（及格）**：基本符合，但有明显的级别错位或用词不当
- **5分（不及格）**：多处表述不符合岗位级别，视角混乱
- **0分（严重）**：完全不符合岗位级别，像初级岗位简历

### 不同级别的表达差异

| 级别 | 关注点 | 典型动词 | 避免表述 |
|------|--------|----------|----------|
| 技术总监 | 战略、决策、价值 | 主导、决策、推动、建立 | 编写代码、调试、配置 |
| 技术经理 | 管理、协调、优化 | 带领、优化、建立、协调 | 学习、尝试、参与 |
| 高级工程师 | 技术、方案、质量 | 设计、实现、优化、解决 | 负责、管理、领导 |
| 工程师 | 实现、学习、成长 | 实现、开发、学习、参与 | 主导、决策、战略 |

### 技术总监表达准则

**核心原则**：
1. 强调决策而非执行
2. 关注价值而非技术细节
3. 突出管理而非个人能力
4. 展示影响力而非工作量

**正确视角**：
- ✅ "决策采用新技术工具，团队效率提升N%"（决策+结果）
- ❌ "使用新工具编写了某功能组件"（执行细节）

- ✅ "主导产品架构设计，选用现代化技术栈"（决策+方案）
- ❌ "精通某框架、某语言等技术开发"（开发岗表述）

- ✅ "推动品牌提升至行业前列，获得相关资质"（影响力+价值）
- ❌ "参与公司品牌建设工作"（参与者视角）

### 检查清单

- [ ] 动词使用符合岗位级别（主导/决策/推动）
- [ ] 避免技术细节堆砌
- [ ] 突出商业价值和影响力
- [ ] 用数据支撑而非形容词
- [ ] 团队成就优先于个人成就

## 4. 框架应用（10分）

### 评分标准

- **10分（优秀）**：每条成就都遵循CAR/STAR原则，逻辑完整
- **8分（良好）**：大部分遵循，有1-2条表述不够完整
- **6分（及格）**：部分遵循，但很多成就缺少背景或结果
- **3分（不及格）**：基本没有框架应用，只罗列职责
- **0分（严重）**：完全是职责描述，无成就展示

### CAR框架（Challenge-Action-Result）

**最适合：产品设计、技术决策、创新项目**

**结构**：
1. **C（Challenge 挑战）**：面临什么问题/困境？
2. **A（Action 行动）**：采取了什么行动/决策？
3. **R（Result 结果）**：取得了什么成果？

**示例**：
```markdown
- **关键决策**：面对X个月传统周期与市场窗口期矛盾（C），
  决策采用新型开发工具（A），团队效率提升N%，
  Y个月完成产品上线（R）
```

### STAR框架（Situation-Task-Action-Result）

**最适合：项目经历、问题解决、团队管理**

**结构**：
1. **S（Situation 情境）**：当时的背景是什么？
2. **T（Task 任务）**：需要完成什么任务？
3. **A（Action 行动）**：采取了什么行动？
4. **R（Result 结果）**：取得了什么结果？

**示例**：
```markdown
- 担任某项目负责人（S），带领N人团队完成关键任务（T），
  通过监控系统发现并阻止重大事件（A），
  获得客户高度认可（R）
```

### PAR框架（Problem-Action-Result）

**最适合：问题解决、技术攻关、危机应对**

### 检查清单

- [ ] 每条成就包含背景/挑战
- [ ] 每条成就说明采取的行动
- [ ] 每条成就量化结果
- [ ] 避免"负责XX工作"的职责描述
- [ ] 因果逻辑清晰

---

## 5. 量化数据（10分）

### 评分标准

- **10分（优秀）**：所有关键成就都有量化数据，数据类型多样
- **8分（良好）**：大部分有量化，少数关键成就缺失
- **6分（及格）**：部分量化，但很多重要成就无数据支撑
- **3分（不及格）**：很少量化，多为定性描述
- **0分（严重）**：完全无量化数据

### 量化数据类型

1. **时间量化**：
   - "N个月完成产品上线（vs 传统X个月）"
   - "项目交付效率提升Y%"
   - "将响应时间从X小时降至Y分钟"

2. **金钱量化**：
   - "年度业绩XX万+"
   - "节省开发成本约YY万"
   - "为客户降低成本N%"

3. **规模量化**：
   - "从0到1组建X人团队"
   - "累计交付YY+项目"
   - "构建ZZZ+功能模块"

4. **效率量化**：
   - "团队效率提升N%"
   - "自动化率达到X%"
   - "处理效率提升Y倍"

5. **比例量化**：
   - "覆盖率从X%提升至Y%"
   - "错误率降低N%"
   - "客户满意度X%+"

### 检查清单

- [ ] 关键成就都有数据支撑
- [ ] 数据类型多样（时间/金钱/规模/效率）
- [ ] 对比数据突出改进（从XX到YY）
- [ ] 避免空洞的形容词（"显著提升"→"提升N%"）
- [ ] 数据真实可验证

## 6. 差异化竞争力（15分）

### 评分标准

- **15分（优秀）**：独特价值主张清晰，竞争优势明显，难以替代
- **12分（良好）**：有差异化亮点，但不够突出
- **8分（及格）**：有一些特点，但不足以形成竞争优势
- **5分（不及格）**：平平无奇，无差异化
- **0分（严重）**：完全同质化，无任何亮点

### 差异化来源

1. **技术创新**：
   - 新技术深度实践
   - 新技术早期采用者
   - 独创方法论或工具

2. **管理成就**：
   - 从0到1搭建团队/产品
   - 品牌提升至行业前列
   - 获得行业资质认证

3. **产品能力**：
   - 完整产品从0到1落地
   - 创新的商业模式
   - 快速商业化验证

4. **行业影响力**：
   - 内容平台运营
   - 标准制定参与
   - 竞赛获奖

5. **复合能力**：
   - 技术+管理+产品三位一体
   - 跨领域融合能力
   - 技术+商业双重视角

### 检查清单

- [ ] 明确的独特价值主张
- [ ] 与同级别候选人的差异点
- [ ] 难以复制的核心能力
- [ ] 行业前沿的技术实践
- [ ] 可量化的影响力

## 7. ATS友好度（10分）

### 评分标准

- **10分（优秀）**：关键词覆盖100%，格式完美兼容ATS
- **8分（良好）**：关键词覆盖80%+，格式基本兼容
- **6分（及格）**：关键词覆盖60%+，格式有部分问题
- **3分（不及格）**：关键词缺失严重，格式不友好
- **0分（严重）**：完全无关键词，格式无法解析

### ATS系统工作原理

**应聘者跟踪系统（ATS）处理流程**：

1. **解析简历**：将PDF/Word转换为结构化数据（姓名、邮箱、经验、技能）
2. **提取关键词**：从简历内容中提取关键词
3. **匹配关键词**：将关键词与职位要求进行匹配
4. **候选人评分**：基于匹配度计算分数
5. **候选人排序**：为招聘者排序候选人列表

**ATS系统的局限性**：
- 难以解析复杂格式（表格、多栏）
- 无法读取图片或图形中的文字
- 不识别非标准节标题
- 对页眉/页脚的解析不可靠
- 无法理解上下文或同义词

### 关键词提取5步法

**步骤1：识别必备技能**

从职位描述的以下位置提取：
- "要求"或"资格"部分
- "必须具备"或"Required"标题
- 技能列表的前几项（通常最重要）

示例提取：
```
职位描述："5年以上Python和Java经验"
           "熟悉云平台（阿里云、AWS）经验"
           "深刻理解微服务架构"

提取关键词：
- Python、Java（编程语言）
- 阿里云、AWS（云平台）
- 微服务架构（架构设计）
```

**步骤2：识别优选技能**

从职位描述的以下位置提取：
- "优选"或"Preferred"部分
- "加分项"或"Plus"标识
- 技能列表的后几项

策略：
- 如果你具备这些技能，务必包含（差异化优势）
- 不要虚构专业知识（面试会被考察）

**步骤3：提取软技能**

常见表明软技能的短语：
- "优秀的沟通能力"
- "有效的团队协作"
- "在快节奏环境中成长"
- "强大的问题解决能力"

包含位置：
- 专业概述部分（如适用）
- 成就描述中（展示而非声称）

**步骤4：捕获行动动词**

从职位描述中提取你将"做什么"或"领导什么"：
- "设计并实现可扩展系统"
- "领导技术计划"
- "与产品和设计团队协作"

在经验部分匹配：
- 使用相同或相似的动词
- "设计并实现..."匹配"设计并实现"

**步骤5：记录技术栈**

明确提及的技术：
- 编程语言
- 框架和库
- 云平台和服务
- 数据库和存储
- 工具和平台

**包含所有适用的技术**，使用精确的术语。

### ATS关键词类型

1. **技术关键词**：
   - 工具：主流工具和平台
   - 技术：相关技术方向
   - 框架：行业标准框架

2. **管理关键词**：
   - 方法：标准化管理方法
   - 能力：团队管理、项目管理、人才培养

3. **行业关键词**：
   - 领域：目标行业领域
   - 场景：应用场景

4. **岗位关键词**：
   - 职位：目标职位名称
   - 资质：相关资质认证

### 关键词匹配策略

**1. 精确匹配优化**

ATS通常寻找精确的短语匹配。

镜像精确术语：
- 职位要求"React.js" → 使用"React.js"而非"React"
- 职位要求"CI/CD" → 使用"CI/CD"而非仅"持续集成"
- 职位要求"Node.js" → 使用"Node.js"而非"Node"或"NodeJS"

**2. 缩写和拼写策略**

同时包含缩写和全称：
```
"持续集成/持续部署（CI/CD）"
"某云服务平台（如AWS）"
"应用程序编程接口（API）"
"RESTful APIs（REST）"
```

这样可以捕获任一形式的搜索。

**3. 同义词覆盖**

在自然的情况下包含多种表述：
```
技能：React、React.js、ReactJS（有些ATS会区分）
前端开发经验、前端开发
构建Web应用、Web应用开发、Web开发
```

**4. 频率考量**

**不要关键词堆砌**，但：
- 重要技能可以在技能和经验部分都出现
- 自然的重复会强化关键词
- 上下文很重要（ATS可能按部分加权）

### ATS友好度测试工具

**在线ATS模拟器**：

估算ATS兼容性的工具：
- 智联招聘ATS检测器（比对简历与职位描述）
- Resume Worded（ATS评分）
- 拉勾网简历优化工具（免费评估）

**注意**：这些工具模拟但不能完全复制真实ATS行为。

**自查清单**：

1. [ ] 包含职位描述中的所有必备关键词
2. [ ] 使用标准节标题
3. [ ] 单栏布局
4. [ ] 无图片、图形或图标
5. [ ] 基于文本的PDF格式
6. [ ] 同时包含缩写和全称
7. [ ] 文件名专业规范

**人工可读性测试**：

ATS优化后，确保简历仍然：
- 对人类读者自然流畅
- 讲述连贯的职业故事
- 没有关键词堆砌
- 突出真实成就

4. **岗位关键词**：
   - 职位：目标职位名称
   - 资质：相关资质认证

### ATS友好格式

✅ **推荐格式**：
- 标准字体（宋体/黑体/Arial）
- 简洁排版（单栏）
- Markdown或纯文本
- PDF格式（保持格式）

❌ **避免使用**：
- 表格（ATS难以解析）
- 文本框
- 图片（除非必需）
- 页眉页脚
- 复杂排版（双栏/多栏）

### 检查清单

- [ ] 包含岗位要求的所有硬性关键词
- [ ] 技术关键词覆盖率80%+
- [ ] 行业术语准确使用
- [ ] 格式简洁规范
- [ ] 使用标准节标题

## 8. 细节完善度（10分）

### 评分标准

- **10分（优秀）**：零错误，无冗余，无遗漏，精益求精
- **8分（良好）**：1-2处小瑕疵，不影响整体质量
- **6分（及格）**：3-5处问题，需要修正
- **3分（不及格）**：多处明显问题
- **0分（严重）**：严重的错误或遗漏

### 检查清单

**语言层面**：

## 评分流程

1. **逐维度评分**：按照8个维度分别评分
2. **计算总分**：Sum(各维度得分)
3. **识别问题**：得分<满分的维度需要改进
4. **优先级排序**：
   - Critical（<60%满分）：必须立即修复
   - High（60-80%）：优先修复
   - Medium（80-95%）：建议优化
   - Low（95-100%）：可选完善

5. **生成报告**：
   ```
   ## 简历评分报告

   **总分**: XX/100

   ### 各维度得分
   - 信息准确性: XX/15
   - 结构合理性: XX/15
   - 专业表达: XX/15
   - 框架应用: XX/10
   - 量化数据: XX/10
   - 差异化竞争力: XX/15
   - ATS友好度: XX/10
   - 细节完善度: XX/10

   ### 主要问题
   1. [Critical] ...
   2. [High] ...

   ### 优化建议
   1. ...
   2. ...
   ```

## 目标分数

- **90-100分**：优秀简历，可直接投递
- **80-89分**：良好简历，少量优化后投递
- **70-79分**：及格简历，需要重点优化
- **<70分**：不合格简历，需要大幅改写
